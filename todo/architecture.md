## 2. Smart contracts (`olive_blockchain/`)

```
contracts/
  interfaces/IBatchRegistry.sol   shared: the only thing B imports from A
  interfaces/IOliveCoin.sol       shared: only if needed
  registry/BatchRegistry.sol      Person A: ERC-721
  payment/OliveCoin.sol           Person B: ERC-20 "OLV"
  payment/PriceCapEscrow.sol      Person B
  libraries/                      pure helpers, only if reused
  mocks/                          test-only mocks of the other person's interface
migrations/                       shared deploy scripts
test/registry · test/payment · test/integration
```

### 2.1 BatchRegistry (Person A, ERC-721)
One NFT is one physical olive oil batch. It is the source of truth for the **physical world**: who holds
the lot, whether it has been quality-certified, and the last declared price. It holds no money.

| Data | Where |
|------|-------|
| Metadata (variety, origin farm, harvest date, quantity in litres) | off-chain JSON; only the URI/hash goes on-chain |
| Current custodian | storage (read by escrow) |
| Certification flag | storage (read by escrow) |
| Last declared price | storage (read by escrow); full history from `PriceRecorded` events |
| Checkpoints (acidity %, polyphenols mg/kg, extraction temp, location, inspector) | **events only**: `CheckpointAdded(batchId, dataHash, inspector)`, with `dataHash` a `bytes32` of the off-chain record |

Roles: `owner/regulator` (sets inspectors and the escrow address), `inspector` (checkpoints and
certification), `custodian` (transfers custody), `escrow` (the only caller of `recordSalePrice`).

### 2.2 OliveCoin + PriceCapEscrow (Person B, ERC-20)
The source of truth for **money and market rules**. It holds no custody or quality data.
- `OliveCoin`: plain OpenZeppelin ERC-20 `OLV`, minted by the market authority for the demo.
- `PriceCapEscrow`: holds buyer OLV until delivery conditions are met. It enforces
  `price <= lastPrice * (100 + maxMarkupPercent) / 100` and has an explicit sale state machine
  (`Created → Deposited → Released | Refunded`).

### 2.3 The only link: `IBatchRegistry`

```
PriceCapEscrow ──reads──►  getLastPrice(batchId)   custodianOf(batchId)   isCertified(batchId)
PriceCapEscrow ──writes─►  recordSalePrice(batchId, price)   (registry checks msg.sender == escrow)
BatchRegistry  ──never calls──► PriceCapEscrow
```

- The escrow imports the **interface**, never `BatchRegistry.sol`.
- Prices are `uint256` in OLV base units (18 decimals) on both sides.
- Deploy order: `BatchRegistry` → `OliveCoin` → `PriceCapEscrow(registry, coin)` → `registry.setEscrow(escrow)`.
- Until the other side is ready, each person tests against a mock in `contracts/mocks/`.

### 2.4 Sale lifecycle across both contracts

```
Farmer        mintBatch(farmer, uri, 200 OLV)                  → BatchMinted, PriceRecorded(200)
Mill operator transferCustody → checkpoints by inspector        → CustodyTransferred, CheckpointAdded
Inspector     certifyBatch                                      → BatchCertified
Distributor   createSale(id, 300)  ✗ reverts (cap = 240 at 20%)
Distributor   createSale(id, 230)  ✓                            → SaleCreated
Grocery       OLV approve + deposit(saleId)                     → Deposited
Distributor   transferCustody(id, grocery)                      → CustodyTransferred
Anyone        releasePayment(saleId): certified ✓, custodian == grocery ✓
              → OLV to seller, registry.recordSalePrice(id, 230) → PaymentReleased, PriceRecorded(230)
```

## 3. Web UI (`olive_web/`)

```
src/
  app/                    routes (shared): layout.tsx, page.tsx, registry/page.tsx, market/page.tsx
  lib/                    shared, change with a Decisions Log entry
    chain.ts              Ganache constants (chain 1337, network 5777, RPC URL)
    contracts.ts          getContract(name, signer?) / getDeployment / getReadProvider
    wallet/WalletProvider.tsx   React context: connect, account, chainId, switch/add Ganache, getSigner
  components/             shared UI: WalletButton, ConnectionStatus
  contracts/deployments.json  GENERATED (git-ignored), { ContractName: { address, abi } }
  features/registry/      Person A screens + hooks  (olive batches, custody, checkpoints)
  features/payment/       Person B screens + hooks  (OLV balance, sales, escrow)
  types/ethereum.d.ts     window.ethereum typing
scripts/sync-contracts.mjs  Truffle build → deployments.json (network 5777)
```

**Data flow**
- **Reads** go straight to Ganache through `getContract(name)` (a `JsonRpcProvider`), so screens work before a wallet is connected.
- **Writes** use `getContract(name, await getSigner())`, so MetaMask signs every transaction. The UI never sees a private key.
- **History** (checkpoints, price history, sales) comes from contract **events** (`contract.queryFilter`), not extra storage.
- **Rules** are enforced on-chain. The UI may pre-check (for example show the price cap) only to give a nicer message.
- Pages are thin server components that render one `"use client"` feature component (wallet access needs the browser).

**Contract → UI pipeline**

```bash
cd olive_blockchain && npm run migrate   # truffle migrate --reset + sync-contracts
cd olive_web && npm run dev              # predev also runs sync-contracts
```

`getContract` returns `null` for a contract that isn't deployed yet, and the screens show "not deployed" instead of crashing.

## 5. Key technical decisions

| Decision | Reason |
|----------|--------|
| solc **0.8.24**, `evmVersion: "paris"`, optimizer 200 runs | Ganache 7 doesn't support Shanghai/Cancun opcodes (`push0`, `mcopy`) |
| OpenZeppelin **5.0.2** (not 5.1+) | Newer versions use `mcopy` and fail to compile for `paris` |
| Checkpoints and price history as events | Gas: history is read off-chain only |
| UI in its own folder (`olive_web/`) | Keeps the Truffle project contracts-only; each side has its own `package.json` |
| ABIs/addresses generated, not committed | Addresses change on every Ganache reset or `migrate --reset` |
| ethers v6 + plain React context (no wagmi) | One local chain and one wallet; fewer dependencies |
| `isCertified` instead of `isValidated` | Reflects olive oil industry language (quality certification vs generic validation) |
| Token symbol `OLV` | Short, recognizable, unambiguous for the olive oil domain |
